Chapter 01
State Management का परिचय
इस chapter में हम सीखेंगे: State क्या होती है, State Management क्या है, यह क्यों जरूरी है, और real-life examples से इसे समझेंगे।

1.1 State क्या है? (What is State?)

Real-life Example — एक light switch की कल्पना करो:

जब switch ON है → बल्ब जल रहा है → यही उसकी State है
जब switch OFF है → बल्ब बुझा है → यह दूसरी State है

यानी — किसी चीज़ की अभी की condition/अवस्था को State कहते हैं।

Technical Definition: State वह data है जो आपके app में किसी समय पर store होता है और जिसके बदलने पर app की UI (screen) बदल जाती है।

जब आप कोई app use करते हैं:

  • 🛒 Shopping cart में कितने items हैं? → यह एक State है
  • 🔔 Notification badge पर number → यह एक State है
  • 😊 Dark mode ON है या OFF? → यह एक State है
  • 👤 User logged in है या नहीं? → यह एक State है
  • 📊 Loading हो रहा है या data आ गया? → यह एक State है
💡 सरल भाषा में:

State = App की "याददाश्त" (Memory)
जब State बदलती है → Screen (UI) automatically update होती है।

1.2 State Management क्या है?

Real-life Example — एक Restaurant की कल्पना करो:

एक बड़े restaurant में:
• 50 tables हैं
• हर table पर orders अलग हैं
• Kitchen को पता होना चाहिए कि कौन सा order किस table के लिए है
• बिल सही आना चाहिए
• अगर कोई dish cancel हो तो सबको update मिलनी चाहिए

इस सब को manage करना ही State Management है!

State Management का मतलब है: App में data (State) को सही तरीके से:

  • Store करना
  • Update करना
  • सही जगह पहुंचाना
  • UI को automatically update करना

1.3 State Management क्यों जरूरी है?

⚠️ बिना State Management के क्या होता है?
  • Data एक जगह update हुआ, दूसरी जगह नहीं → Bug!
  • Screen update नहीं होती जब data बदला → Bug!
  • Code बहुत complicated हो जाता है → Maintainability Problem!
  • Team members के code में conflict → Development Problem!
✅ State Management से क्या फायदा?
  • Data हमेशा consistent रहता है
  • UI automatically update होती है
  • Code clean और organized रहता है
  • Team में काम करना आसान होता है
  • App fast और efficient रहती है
  • Bugs ढूंढना और fix करना आसान होता है

1.5 State vs Variable — क्या फर्क है?

🤔 यह सवाल हर beginner पूछता है!

Variable और State में क्या अंतर है? दोनों data store तो करते हैं...

पहलू Variable (साधारण) State (Managed)
UI Update ❌ नहीं होती automatically ✅ automatically होती है
Reactivity ❌ Reactive नहीं है ✅ Reactive है
कब use करें जब UI बदलनी न हो जब UI update करनी हो
Example int x = 5; setState(() { count = 5; })
Flutter में Normal variable State object
Dart — Variable vs State 
// ❌ यह काम नहीं करेगा — UI update नहीं होगी
class WrongExample extends StatelessWidget {
  int count = 0;  // साधारण variable
  
  onPressed() {
    count++;  // value तो बढ़ी, पर UI नहीं बदलेगी!
  }
}

// ✅ यह सही है — UI automatically update होगी
class CorrectExample extends StatefulWidget {
  _CorrectExampleState createState() => _CorrectExampleState();
}

class _CorrectExampleState extends State<CorrectExample> {
  int count = 0;  // State variable
  
  onPressed() {
    setState(() {
      count++;  // अब UI automatically update होगी!
    });
  }
}

💼 Interview Questions — Chapter 1

Q1
Flutter में State क्या होती है? Simple words में explain करो।
Answer: State वह data है जो app में किसी time पर exist करता है और जिसके बदलने पर UI automatically update होती है। जैसे — counter की value, login status, cart में items की संख्या — ये सब State हैं।
Q2
State Management क्यों important है? बिना इसके क्या problem होती है?
Answer: State Management important है क्योंकि:
1. Data consistency — एक जगह update हो तो सब जगह reflect हो
2. UI synchronization — State बदले तो screen automatically update हो
3. Code maintainability — बड़े apps में code organized रहे

बिना State Management के: data inconsistency, UI bugs, messy code जैसी problems होती हैं।
Q3
StatefulWidget और StatelessWidget में क्या फर्क है?
Answer:
StatelessWidget: जिसकी State नहीं होती — यह एक बार बना और fixed रहा। जैसे — एक static text या image।
StatefulWidget: जिसकी State होती है — यह data बदलने पर rebuild होता है। जैसे — counter, form, animation।
Chapter 02
State के प्रकार (Types of State)
State कई तरह की होती है। इस chapter में हम समझेंगे — Local, Global, Shared, UI, App, Server, Persistent और Temporary State क्या होती हैं।
💡 यह Chapter क्यों जरूरी है?

अलग-अलग तरह की State को अलग-अलग तरीके से manage करना पड़ता है। जब आप जान जाएंगे कि आपकी State किस type की है, तो आप सही State Management solution चुन पाएंगे।

2.1 Local State (स्थानीय State)

Real-life Example: एक drawer के अंदर रखी चीज़ें। सिर्फ उस कमरे वाले को पता है — बाकी घर को नहीं।

Local State वह State है जो सिर्फ एक Widget तक limited होती है। दूसरे widgets को इसकी जरूरत नहीं होती।

Dart — Local State Example 
class ExpandableCard extends StatefulWidget {
  _ExpandableCardState createState() => _ExpandableCardState();
}

class _ExpandableCardState extends State<ExpandableCard> {
  // यह Local State है — सिर्फ इस widget को पता है
  bool isExpanded = false;
  
  Widget build(BuildContext context) {
    return GestureDetector(
      onTap: () => setState(() => isExpanded = !isExpanded),
      child: Column(
        children: [
          Text('Card Title'),
          if (isExpanded) Text('Card Content...'),
        ],
      ),
    );
  }
}

2.2 Global State (वैश्विक State)

Real-life Example: देश की temperature — पूरे देश को affect करती है।

Global State वह State है जो पूरे app में accessible होती है। कोई भी widget इसे पढ़ और update कर सकता है।

Examples:

  • User authentication status (logged in / logged out)
  • App theme (dark/light mode)
  • User language preference
  • Shopping cart data

2.3 Shared State (साझा State)

Real-life Example: एक family का shared bank account — कोई भी member debit/credit कर सकता है।

Shared State वह State है जो कई widgets के बीच share होती है — लेकिन जरूरी नहीं कि पूरे app में हो।

2.4 UI State

UI से related State — जैसे:

  • Dialog open है या नहीं
  • Tab selection
  • Scroll position
  • Animation state
  • Form validation errors

2.5 App State

पूरे app की State जो multiple screens पर share होती है:

  • User profile data
  • App settings
  • Notification count
  • Online/offline status

2.6 Server State

Real-life Example: Weather app में temperature — data server से आता है और बदलता रहता है।

Server से आने वाला data जो:

  • Asynchronous (time लेता है)
  • Cache में store हो सकता है
  • Loading, Success, Error states होती हैं
  • Background में refresh होता है

2.7 Persistent State

Real-life Example: Phone का WiFi password — app close होने पर भी याद रहता है।

App close होने के बाद भी store रहने वाली State:

  • User preferences (SharedPreferences)
  • Login token (Secure Storage)
  • Offline data (SQLite/Hive)
  • App settings

2.8 Temporary State

Short time के लिए exist करने वाली State:

  • Form input values
  • Dropdown selections
  • Search query text
  • Timer countdown

Order placed → Order confirmed → Order shipped → Order delivered → Order completed

3.2 Flutter Widget Lifecycle

📌 Flutter में State का Widget Lifecycle

Flutter में StatefulWidget के साथ State का lifecycle कुछ important methods से जुड़ा है।

Flutter StatefulWidget Lifecycle
createState()
→ Widget create होता है
initState()
→ State initialize होती है
didChangeDependencies()
→ Dependencies बदलती हैं
build()
→ UI render होती है
setState() → rebuild()
→ State बदली → UI update
deactivate()
→ Widget temporarily हटाया
dispose()
→ Widget permanently destroy
Dart — Complete Widget Lifecycle 
class MyWidget extends StatefulWidget {
  _MyWidgetState createState() => _MyWidgetState(); // Step 1
}

class _MyWidgetState extends State<MyWidget> {
  int count = 0;
  
  // Step 2: Widget screen पर पहली बार आने पर
  @override
  void initState() {
    super.initState();
    print('Widget created! यहाँ API calls या initialization करो');
    // यहाँ: API call, timer start, listener setup
  }
  
  // Step 3: हर बार UI build होती है
  @override
  Widget build(BuildContext context) {
    print('Build हुई! count = $count');
    return Scaffold(
      body: Center(
        child: Column(
          children: [
            Text('Count: $count'),  // State READ
            ElevatedButton(
              // State UPDATE
              onPressed: () => setState(() => count++),
              child: Text('Increment'),
            ),
          ],
        ),
      ),
    );
  }
  
  // Step 4: Widget screen से हटने पर — cleanup करो
  @override
  void dispose() {
    print('Widget destroy! Cleanup करो');
    // यहाँ: timer cancel, stream close, controller dispose
    super.dispose();
  }
}

3.5 State UPDATE करना

⚠️ Important Rule:

State को हमेशा setState() के अंदर update करो, नहीं तो UI update नहीं होगी!

Dart — State Update 
// ❌ गलत तरीका — UI update नहीं होगी
count++;  // setState के बाहर

// ✅ सही तरीका — UI automatically update होगी
setState(() {
  count++;
  name = 'Flutter Developer';
  isLoading = false;
});

3.6 State DELETE करना (dispose)

Dart — State Cleanup (dispose) 
class _MyState extends State<MyWidget> {
  TextEditingController _controller = TextEditingController();
  Timer? _timer;
  StreamSubscription? _subscription;
  
  @override
  void initState() {
    super.initState();
    _timer = Timer.periodic(Duration(seconds: 1), (_) => doSomething());
  }
  
  @override
  void dispose() {
    // Memory leak से बचने के लिए cleanup जरूरी है!
    _controller.dispose();  // TextController cleanup
    _timer?.cancel();        // Timer cancel
    _subscription?.cancel(); // Stream close
    super.dispose();
  }
}

Flutter पूरी screen दोबारा नहीं बनाता — सिर्फ वही हिस्सा rebuild करता है जिसकी State बदली है। इसीलिए Flutter इतना fast है!

Chapter 04
State Management के बिना समस्याएं (Problems Without State Management)
जब हम State Management tools का उपयोग नहीं करते हैं, तब हमें Prop Drilling, Data Synchronization, अनावश्यक Re-rendering और Maintainability जैसी समस्याओं का सामना करना पड़ता है।

4.1 Prop Drilling (प्रॉप ड्रिलिंग)

Real-life Example — पानी की पाइपलाइन:

मान लीजिए कि एक बहुमंजिला इमारत (Multi-story building) में 5वीं मंजिल पर पानी पहुंचाना है। आपके पास कोई केंद्रीय टंकी (Central Tank) या पंप नहीं है। आप पहली मंजिल के फ्लैट से पाइप जोड़कर दूसरी मंजिल, फिर तीसरी मंजिल, चौथी मंजिल और अंत में 5वीं मंजिल पर पानी पहुँचाते हैं। 2, 3, और 4 मंजिल के लोगों को पानी की आवश्यकता नहीं है, लेकिन उनके घर से पाइप गुजर रही है। यही Prop Drilling है!

Prop Drilling: जब किसी deep-nested child widget को parent widget से कोई data चाहिए होता है, तो हमें उस data को बीच के सभी widgets (intermediate widgets) के माध्यम से pass करना पड़ता है, भले ही उन intermediate widgets को उस data से कोई लेना-देना न हो।

🔄 Prop Drilling vs Centralized State
Parent Widget (Data: User)
↓ (drilling user)
Middle Widget A (No use of user)
↓ (drilling user)
Middle Widget B (No use of user)
↓ (drilling user)
Deep Child Widget (Uses User Data)
Dart — Prop Drilling Problem 
class ParentWidget extends StatelessWidget {
  final String username = "Amit";
  @override
  Widget build(BuildContext context) {
    return MiddleWidgetA(username: username); // Passing down
  }
}

class MiddleWidgetA extends StatelessWidget {
  final String username;
  MiddleWidgetA({required this.username});
  @override
  Widget build(BuildContext context) {
    return MiddleWidgetB(username: username); // Passing down again
  }
}

class MiddleWidgetB extends StatelessWidget {
  final String username;
  MiddleWidgetB({required this.username});
  @override
  Widget build(BuildContext context) {
    return DeepChildWidget(username: username); // Finally reaching destination
  }
}

class DeepChildWidget extends StatelessWidget {
  final String username;
  DeepChildWidget({required this.username});
  @override
  Widget build(BuildContext context) {
    return Text("Hello, $username");
  }
}

4.2 Data Synchronization (डेटा सिंक्रनाइज़ेशन)

जब एक ही data को app में अलग-अलग जगहों (screens) पर दिखाया जा रहा हो, तो यदि एक जगह data बदलता है, तो दूसरी जगह भी उसे update होना चाहिए। बिना State Management के, आपको हर screen को manual updates भेजने होंगे, जिससे data outdated रह जाता है।

4.3 Re-rendering Issues (अनावश्यक री-रेंडरिंग)

जब आप parent widget में setState() का उपयोग करते हैं, तो वह parent widget और उसके अंतर्गत आने वाले सभी child widgets फिर से build (rebuild) हो जाते हैं, भले ही उनका data बदला हो या नहीं। यह app की performance को धीमा कर देता है।

5.2 Todo Application Example

Dart — Basic Todo App 
class TodoApp extends StatefulWidget {
  @override
  _TodoAppState createState() => _TodoAppState();
}

class _TodoAppState extends State<TodoApp> {
  final List<String> _todos = [];
  final TextEditingController _controller = TextEditingController();

  void _addTodo() {
    if (_controller.text.isNotEmpty) {
      setState(() {
        _todos.add(_controller.text);
        _controller.clear();
      });
    }
  }

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: Text('My Todo App')),
      body: Column(
        children: [
          Padding(
            padding: const EdgeInsets.all(8.0),
            child: Row(
              children: [
                Expanded(
                  child: TextField(
                    controller: _controller,
                    decoration: InputDecoration(labelText: 'Add Task'),
                  ),
                ),
                IconButton(icon: Icon(Icons.add), onPressed: _addTodo),
              ],
            ),
          ),
          Expanded(
            child: ListView.builder(
              itemCount: _todos.length,
              itemBuilder: (context, index) {
                return ListTile(
                  title: Text(_todos[index]),
                  trailing: IconButton(
                    icon: Icon(Icons.delete),
                    onPressed: () {
                      setState(() {
                        _todos.removeAt(index);
                      });
                    },
                  ),
                );
              },
            ),
          ),
        ],
      ),
    );
  }
}

Chapter 07
InheritedWidget
Flutter का internal Low-Level State sharing mechanism. InheritedWidget कैसे काम करता है और इसके क्या फायदे और सीमाएं हैं।

7.1 Concept & Architecture

InheritedWidget Flutter tree में data को नीचे की ओर propagate (प्रसारित) करने की सुविधा देता है ताकि किसी भी child widget को manual constructors के बिना framework के context.dependOnInheritedWidgetOfExactType के माध्यम से data मिल सके।

Dart — InheritedWidget Example 
class SharedData extends InheritedWidget {
  final int data;
  SharedData({required this.data, required Widget child}) : super(child: child);

  static SharedData? of(BuildContext context) {
    return context.dependOnInheritedWidgetOfExactType<SharedData>();
  }

  @override
  bool updateShouldNotify(SharedData oldWidget) {
    return oldWidget.data != data;
  }
}
Chapter 08
Provider State Management
Provider package का उपयोग करके ChangeNotifier, Consumer और MultiProvider की मदद से state को clean तरीके से manage करना।

8.1 ChangeNotifier & Consumer

ChangeNotifier एक Flutter-native class है जो listeners को notify करती है। Provider इसके ऊपर wrapper की तरह काम करता है।

Dart — Provider Counter App 
import 'package:flutter/material.dart';
import 'package:provider/provider.dart';

class CounterProvider with ChangeNotifier {
  int _count = 0;
  int get count => _count;

  void increment() {
    _count++;
    notifyListeners();
  }
}

void main() {
  runApp(
    ChangeNotifierProvider(
      create: (context) => CounterProvider(),
      child: MyApp(),
    ),
  );
}

class MyApp extends StatelessWidget {
  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      home: Scaffold(
        appBar: AppBar(title: Text('Provider Counter')),
        body: Center(
          child: Consumer<CounterProvider>(
            builder: (context, counter, child) {
              return Text('Count: ${counter.count}', style: TextStyle(fontSize: 24));
            },
          ),
        ),
        floatingActionButton: FloatingActionButton(
          onPressed: () {
            Provider.of<CounterProvider>(context, listen: false).increment();
          },
          child: Icon(Icons.add),
        ),
      ),
    );
  }
}
Chapter 09
Riverpod State Management
Provider का आधुनिक रूप — Riverpod। यह compile-time safe है, BuildContext पर निर्भर नहीं करता और flutter_riverpod का उपयोग करना बहुत आसान है।

9.1 Provider Types in Riverpod

  • Provider: Read-only value के लिए।
  • StateProvider: Simple variables को modify करने के लिए।
  • FutureProvider: Asynchronous API calls के लिए।
  • StateNotifierProvider: Custom state classes और complexes logic के लिए।
Dart — Riverpod Example 
import 'package:flutter/material.dart';
import 'package:flutter_riverpod/flutter_riverpod.dart';

final counterStateProvider = StateProvider<int>((ref) => 0);

void main() {
  runApp(ProviderScope(child: MyApp()));
}

class MyApp extends ConsumerWidget {
  @override
  Widget build(BuildContext context, WidgetRef ref) {
    final count = ref.watch(counterStateProvider);
    return MaterialApp(
      home: Scaffold(
        appBar: AppBar(title: Text('Riverpod Counter')),
        body: Center(child: Text('Count: $count', style: TextStyle(fontSize: 24))),
        floatingActionButton: FloatingActionButton(
          onPressed: () => ref.read(counterStateProvider.notifier).state++,
          child: Icon(Icons.add),
        ),
      ),
    );
  }
}

💡 Common Mistakes to Avoid

  • Mistake 1: APIs directly inside build() method! (यह application को freeze/infinite request loop में डाल देता है)।
  • Mistake 2: setState() on disposed controllers or contexts! (हमेशा check करें if (mounted))।
  • Mistake 3: Store controllers and instances globally without closing them, causing huge memory leaks.

🎓 100+ Interview Preparation Questions (Sample)

Q1
What is the main difference between Provider and Riverpod?
Riverpod doesn't rely on BuildContext, meaning it can be read from anywhere. It checks errors during compile-time rather than runtime, solving multiple Provider issues like ProviderNotFoundException.
Q2
What are reactive streams?
Streams are sequences of asynchronous events. Modern state management systems like MobX, Bloc, and GetX utilize streams/observables to automatically broadcast updates to UI components subscribing to them.
